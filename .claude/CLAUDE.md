# 面试复习笔记

面向 **AI 产品**、**全栈开发**（前端 + Java 后端）、**AI 应用开发** 三类岗位的面试复习笔记。目录设计和依据见 [README.md](../README.md)。

## 内容放在哪里

- 还没写的笔记开头有一行「范围」，是早期临时写的，不一定对，只作参考。开始写某篇笔记时直接删掉这一行，不用向用户提起；这篇笔记的边界以确认后的目录为准。
- 同一个知识点只写一处，其他笔记用 Markdown 链接引用，不要在两个地方各写一份。
- `技术/全栈开发/共通/` 只放前后端都要学的内容；只有前端或只有后端要学的放 `前端/`、`后端/`。
- `产品/AI产品/技术理解` 只写产品需要懂到的程度，原理写在 `技术/AI应用开发/`，用 Markdown 链接过去。这种链接会被站点收成引用关系：笔记底部列出「引用 / 被引用」，「关联」页汇总全部。
- `产品/` 下「要懂什么」放知识目录，「怎么答」放 `面试题型/`。
- 面经放 `面经与复盘/`，格式见那里的 README；复盘出的知识点写回对应的知识文件。
- 新增目录项时同步更新 README 的目录结构；如果它在 JD 里有对应要求，在 `tools/scripts/jd_analysis.py` 的 `ITEMS` 里加一行关键词，重新生成图。

## 写一篇笔记的流程

按下面四步走，每步做完停下来等用户确认，再进入下一步。

### 1. 收集参考资料

- **从哪找**：技术笔记先从 `../项目/github-fullstack-topk/`、`../项目/github-ai-topk/` 两份项目图谱里按分类和关键词筛；再上网补图谱之外的资料（经典教材、课程、中文面试资料、官方文档、规范原文）。考点的侧重可以参考 `../互联网社招/data` 里的 JD。
- **放在哪**：`../参考/`，在 `面试/` 仓库之外，约定见 `../参考/README.md`。
  - 要克隆的仓库加进 `repos.txt`，运行 `./sync.sh`，浅克隆到 `repos/<owner>/<repo>/`，一个仓库只存一份，多篇笔记共用。
  - 规范、标准、论文等原文放 `docs/<类别>/`。
  - 每篇笔记在 `清单/` 下有一份参考清单，路径和笔记一一对应。清单写明用到哪个仓库的哪些具体文件、各资料的用途和可信度，以及和其他笔记的边界。
- 只有读源码时才用得上的大型代码仓库，写笔记用不到，只在清单里列出，不克隆。

### 2. 核实：参考资料只是参考

参考资料可能有错、互相矛盾或已经过时，不能照搬。

- 写进笔记的每个结论，都要以规范原文、官方文档或官方公告为准，二手资料只用来找考点。
- 容易过时的内容（版本、默认值、标准的最新状态、厂商和浏览器的支持情况）要上网查最新状态，并把结论、来源链接、核实日期记进清单的「已核实的时效信息」。
- 目录条目本身也要核实。条目往往是从资料里沿用的说法，里面可能带着过时或误导的前提：比如把某个旧版本、某种经典模型当成现状，或者问题的问法本身就预设了一个不成立的结论。
- 资料之间有矛盾时，在笔记里写明正确说法和常见的错误说法。

### 3. 写目录，给用户确认

目录要同时满足以下几条：

- **循序渐进**：概念先于使用，不提前引用后面才讲的概念。写完逐条检查：每个条目用到的概念是否已经在前面讲过。
- **概念导向，不是问题导向**：每章前面的小节用陈述式标题讲清「是什么、怎么工作」；面试题集中放在每章最后的「常见追问」。每条追问只能依赖本章和前面章节的内容，否则挪到后面的章节。
- **面试完整**：对照参考资料里的高频题清单查漏。
- **边界清楚**：和其他笔记重叠的内容，只在一处展开，其他地方用 Markdown 链接引用，比如 `见[笔记标题](相对路径.md)`，不要写成「写在「某某笔记」」这种纯文本。
- 每章开头如果需要承接前文，用一节「要解决的问题」说明这一章为什么存在。

### 4. 按章写正文

- 先写第一章给用户看，确认风格后再继续；之后每写完一章都请用户过目。
- 没写完的笔记保留「（待补充）」标记：`build_site.py` 靠它判断一篇笔记是否写完。分章写时，把它放在还没写的章节前面，比如 `以下章节（待补充），目前只有目录。`
- 写完用浏览器打开本地预览，逐个点一遍交互，深色和浅色主题都要看。

## 写法

- **图文并茂、结构化**：每个概念优先用「图或表 + 几条要点」来表达，不写大段文字。要点用加粗关键词开头，例如 `- **关键词**：……`。
- **类比、易混点、结论**放引用块：`> **要点**：……`、`> **类比**：……`、`> **易混**：……`。
- **表格**适合做对比和汇总。
- **常见追问**写成点击展开的自测题，让读者先自己想，再看答案：

  ```markdown
  <details>
  <summary>问题？</summary>

  - **结论一**：……
  - **结论二**：……

  </details>
  ```

- **引用都要能点击跳转**，并尽量跳到具体小节：
  - 同一篇里：`见 [2.3](#23-小节标题)`；在 HTML 块里写成 `<a href="#23-小节标题">2.3</a>`。
  - 跨笔记：`见[笔记标题](相对路径.md#小节锚点)`。
  - 锚点规则和 GitHub 一致：标题转小写，去掉标点（包括中文标点和 `.`），空白换成连字符，重名的依次加 `-1`、`-2`。例如 `### 2.3 某某：原理` 的锚点是 `23-某某原理`。站点的 `app.js` 和 `build_site.py` 各有一份 `slugify`，改规则时两边一起改。
  - `build_site.py` 会检查所有带锚点的链接，指向不存在的标题时会列出来。改了标题名要重新构建，把报出来的链接修好。
- **目标笔记还没写时**：先链接到整篇笔记，紧跟着加一条注释 `<!-- TODO(锚点)：目标笔记写好后，改成链接到讲「某某」的小节 -->`。写完一篇笔记后，运行 `rg 'TODO\(锚点\)' -g '*.md'`，把指向这篇的 TODO 链接改成具体小节，再删掉注释。

## 交互图

图直接用 HTML 写在 Markdown 里，交互由 `site/assets/figures.js` 提供，样式在 `site/assets/style.css` 的「笔记里的图」部分。

**交互只用点击，不用悬停**，也不要用 `title` 属性做悬停提示：悬停要等，在手机上也用不了。

通用组件：

| 组件 | 适合 | 写法 |
|---|---|---|
| `.fig-steps` 分步演示 | 流程、时序、状态变化 | 图里的元素加 `data-node`；`.fig-list > li` 是各个步骤，`data-on` 列出这一步要高亮的节点，`data-label` 是步骤按钮上的短名 |
| `.fig-hl` 联动高亮 | 对照、结构、组成部分 | 可点击的元素加 `data-key`，key 相同的一起高亮；`.fig-note[data-key]` 是选中后显示的说明，`.fig-hint` 是没选中时的提示 |

`figures.js` 里还有为个别笔记写的专用组件，用法看代码，不要当成通用写法。

通用的布局类：`.fig-cap` 是图的说明文字；`.fig-flow` 配 `.fig-box`、`.fig-wire` 画横向的节点和连线，节点下方要挂分支时用 `.has-below`、`.fig-drop`、`.fig-below`、`.fig-vwire`；`.fig-notes` 是图下方的说明区。其他为个别图写的布局见 `style.css`。静态示意图可以直接写内联 `<svg>`，文字和线条用 `currentColor`，以适配深浅主题；`marker` 等元素的 `id` 要全站唯一。

需要新的交互时，优先在 `figures.js` 里加通用组件；只有确实无法通用时，才写某张图的专用逻辑。

写 HTML 时注意这几个坑：

- **HTML 块里不能有空行**：marked 遇到空行就结束 HTML 块，后面的内容会被当成 Markdown 解析，缩进的行还会变成代码块。
- **HTML 块里不解析 Markdown**：要用 `<b>`、`<code>`、`<br>` 等标签。
- **指向其他笔记的链接写在 HTML 块外面**，用 Markdown 语法：`build_site.py` 只从 Markdown 链接收集引用关系。
- **在 GitHub 上看源文件时交互会失效**（`class`、`data-*` 会被过滤），所以要保证内容能退化成可读的列表和表格。例如分步演示的每个步骤里都要写完整的文字，不能只靠高亮来表达。

## 隐私

仓库会公开。简历原文、真实薪资、面试官信息、公司要求保密的题目都不要写进普通文件；需要记录的写进 `*.private.md`（已被忽略）。提交前检查 `git status` 里没有这类内容。

## 站点

改了任何笔记 Markdown 后，提交前跑 `python3 tools/scripts/build_site.py` 重新生成 `site/data/notes.json`，两个一起提交。推到 `main` 后 GitHub Actions 会把 `site/` 部署到 GitHub Pages。不要手改 `site/data/notes.json`。

本地预览用 `python3 -m http.server -d site 8000`，不能直接双击 html。
