### 1.2 分层模型

**为什么要分层**

- **分工**：每层只解决一类问题，只和相邻的层打交道：使用下层提供的服务，为上层提供服务
- **可替换**：某一层换实现，其他层不受影响。比如从网线换成 Wi-Fi，TCP 和 HTTP 完全不用改
- **类比寄快递**：你只管写好信（应用层），写明收件人和地址（传输层、网络层），快递公司再分段运输（链路层、物理层）；你不需要知道信坐的是卡车还是飞机

学习时最常用的是**五层模型**：TCP/IP 四层，再把网络接口层拆回链路层和物理层。本笔记后面都按五层来讲。

> **别混淆编号**：业界说的「二层交换机」「三层路由」「四层负载均衡」「七层负载均衡」沿用的是 OSI 的编号：二层 = 链路层，三层 = 网络层，四层 = 传输层，七层 = 应用层。

**各层一览**

| 层（五层模型） | 负责什么 | 数据单位 | 代表协议 | 相关设备 | 详见 |
|---|---|---|---|---|---|
| 应用层 | 应用之间交换什么内容、按什么格式 | 报文（消息） | HTTP、DNS、WebSocket、TLS¹ | 代理、七层负载均衡 | [第 5 章](#5-dns)～[7](#7-https-与-tls)、[11](#11-websocket-协议) 章 |
| 传输层 | 把数据交给对方主机上的正确进程；TCP 还负责可靠传输、流量控制和拥塞控制 | TCP 报文段、UDP 数据报 | TCP、UDP、QUIC² | 四层负载均衡 | [第 3 章](#3-传输层tcp)、[4](#4-传输层udp) 章 |
| 网络层 | 跨网络寻址和选路，把数据从源主机送到目的主机 | IP 数据报（包） | IP、ICMP | 路由器 | [第 2 章](#2-网络层与链路层) |
| 链路层 | 在同一段链路上，把数据交给下一个节点 | 帧 | 以太网、Wi-Fi、ARP³ | 交换机 | [第 2 章](#2-网络层与链路层) |
| 物理层 | 把比特变成电信号、光信号或无线电波 | 比特 | — | 网卡、网线、光纤 | — |

¹ TLS 在 TCP 之上、HTTP 之下，四层模型里通常归入应用层。\
² QUIC 运行在 UDP 之上，但承担了可靠传输、拥塞控制等传输层职责，一般归为传输层。\
³ ARP 负责把 IP 地址转换成 MAC 地址，一般归入链路层。

- **发送方**从上往下逐层加头，**接收方**从下往上逐层拆头，每层只读自己这一层的头
- **每个头里都记着「上一层是谁」**，接收方据此把数据交给正确的上层：帧头的类型字段指向 IP，IP 头的协议号指向 TCP，TCP 头的端口指向具体哪个应用
- **中间设备只拆到自己那一层**：交换机只看帧头，路由器看到 IP 头为止，TCP 头和 HTTP 内容它们都不关心
- **HTTPS 多一步**：HTTP 报文先被 TLS 加密，再交给 TCP
- **头部是开销**：以太网一帧最多装 1500 字节（MTU，见 [2.2](#22-路由与转发)），去掉 IP 头和 TCP 头各 20 字节，一个 TCP 报文段最多装约 1460 字节数据（MSS，见 [3.2](#32-报文头部与连接标识)）

### 1.3 三种地址

> **类比寄快递**：**IP 地址**是收件地址（哪栋楼），**端口**是收件人（楼里的哪个人），**MAC 地址**是每一段运输中「下一站交给谁」，每换一段路就换一次。

| | MAC 地址 | IP 地址 | 端口 |
|---|---|---|---|
| 标识什么 | 一个网络接口（网卡） | 网络中的一台主机（一台主机可以有多个 IP） | 主机上的一个应用进程 |
| 所在层 | 链路层 | 网络层 | 传输层 |
| 长度 | 48 位 | IPv4 32 位，IPv6 128 位 | 16 位（0～65535） |
| 有效范围 | 同一个局域网内 | 全网，端到端 | 一台主机内 |
| 怎么来的 | 出厂时写入网卡；手机连 Wi-Fi 时通常默认使用随机 MAC | DHCP 自动分配，或手动配置 | 服务端固定监听（HTTPS 443、SSH 22）；客户端由系统临时分配 |
| 例子 | `3c:22:fb:12:34:56` | `192.168.1.10`、`2001:db8::1` | `443`、`52814` |

- **MAC 每一段都变，IP 端到端不变**（经过 NAT 时例外）：MAC 管「这一段交给谁」，IP 管「最终送到哪」
- **路由器的每个接口**都有自己的 MAC 地址和 IP 地址
- **下一站的 MAC 怎么知道**：用 ARP 根据下一站的 IP 查出来（[2.3](#23-arp)）
- **端口让一台主机能同时运行多个网络程序**：服务器靠目的端口区分是哪个服务，靠「源 IP + 源端口」区分是哪个客户端（完整的连接标识见 [3.2](#32-报文头部与连接标识)）

### 1.4 性能度量

| 指标 | 含义 | 单位 | 类比：用水管送水 | 日常在哪看到 |
|---|---|---|---|---|
| 带宽 | 链路每秒最多能传多少数据 | Mbps（兆比特每秒） | 水管有多粗 | 宽带套餐的「500 兆」 |
| 延迟 | 数据从一端到另一端要多久（单程） | ms | 水管有多长 | 平时说的「延迟」多数其实指 RTT |
| RTT | 发出一个包到收到对方回应的往返时间 | ms | 喊一声到听见回音 | `ping` 输出里的 `time` |
| 吞吐量 | 实际每秒传了多少数据，不会超过带宽 | Mbps 或 MB/s | 实际流过的水量 | 下载速度 |

> **单位别混**：带宽用**比特**（b），下载速度常用**字节**（B），1 B = 8 b。100 Mbps 的宽带，下载速度上限约 12.5 MB/s。

**延迟从哪来**

| 组成 | 原因 | 怎么降 |
|---|---|---|
| 传播延迟 | 信号走过物理距离需要时间，光在光纤中约 20 万 km/s | 只能缩短距离（CDN 就近接入） |
| 传输延迟 | 把数据全部推上线路：数据量 ÷ 带宽 | 加带宽，或减少数据量（压缩） |
| 排队延迟 | 路由器繁忙时，包在缓冲区里排队 | 网络拥塞时明显变大 |
| 处理延迟 | 设备检查头部、查路由表 | 通常很小 |

> **光速是硬限制**：北京到广州直线约 1900 km，光在光纤里单程至少约 10 ms，RTT 至少约 20 ms，实际线路有绕行，只会更长。

**为什么后面都用「几个 RTT」衡量快慢**

- 建立连接、握手的每一步都要等对方回应，每等一次就是一个 RTT
- 距离一定时 RTT 几乎降不下来，所以优化只有两个方向：**减少往返次数**（TLS 1.3、HTTP/3、连接复用）和**把服务器放近**（CDN）
- 网页上的请求大多很小，传输时间只占一小部分，往返等待才是大头

用下面的计算器试试：把带宽从 100 Mbps 调到 1000 Mbps，总耗时几乎不变；把 RTT 调大，各协议的差距立刻拉开。各协议为什么是这些往返次数，见 [7.5](#75-tls-13) 和 [9.2](#92-quic-的连接建立)。

### 1.5 常见追问

<details>
<summary>为什么实际用的是四层模型，而不是七层？</summary>

- **先有实现**：TCP/IP 先在 ARPANET 上跑起来，又随 BSD Unix 等系统普及，成了事实标准；OSI 模型发布得更晚，配套协议也更复杂
- **会话层、表示层没必要单独成层**：会话管理、加密、编码实际由应用或库自己完成（如 TLS、gzip、JSON），并入应用层更自然
- **两个模型并用**：讲协议用 TCP/IP 模型；业界说「二层、三层、四层、七层」沿用 OSI 的编号

</details>

<details>
<summary>一个 HTTP 请求在每一层分别被加上了什么？</summary>

- **应用层**：HTTP 报文本身（请求行、头部、正文）；如果是 HTTPS，先被 TLS 加密
- **传输层**：TCP 头，至少 20 字节，关键字段是源端口、目的端口、序号
- **网络层**：IP 头，IPv4 至少 20 字节，关键字段是源 IP、目的 IP、TTL
- **链路层**：以太网帧头 14 字节（源 MAC、目的 MAC、类型），加上帧尾校验 4 字节
- **物理层**：变成比特，以电信号、光信号或无线电的形式发出去

</details>

<details>
<summary>有了 IP 地址，为什么还需要 MAC 地址？</summary>

- **分工不同**：IP 负责「最终送到哪台主机」，要跨越多个网络；MAC 负责「在当前这段链路上交给谁」
- **链路层有多种技术**：以太网、Wi-Fi 各有自己的帧格式和地址，IP 作为统一的一层架在它们之上，不关心下面用的是什么
- **反过来，只有 MAC 也不行**：MAC 地址按厂商分配，和设备在网络中的位置无关，路由器没法按它汇总路由；IP 地址按网段划分，才能逐级转发（[2.2](#22-路由与转发)）

</details>

<details>
<summary>交换机和路由器有什么区别？家里的「路由器」是哪一种？</summary>

| | 交换机 | 路由器 |
|---|---|---|
| 所在层 | 链路层（二层） | 网络层（三层） |
| 依据什么转发 | 目的 MAC | 目的 IP（查路由表） |
| 连接的是 | 同一个局域网内的设备 | 不同的网络 |
| 转发时改什么 | 不改 | 换掉帧头里的源、目的 MAC，IP 头里的 TTL 减 1 |

家用「路由器」其实是几样东西的组合：路由器 + 交换机（那几个 LAN 口）+ 无线接入点 + NAT + DHCP 服务。

</details>

<details>
<summary>带宽越大，网页打开就越快吗？</summary>

- **不一定**：网页的请求大多很小，时间主要花在 DNS、TCP、TLS 这些往返等待上，传数据只占一小部分（可以用 1.4 的计算器验证）
- **两者影响的场景不同**：带宽决定「管道多粗」，影响下载大文件；RTT 决定「每次往返多久」，影响打开网页、调用接口这类小请求
- **所以提速靠的是**：减少往返（TLS 1.3、HTTP/3、连接复用）和缩短距离（CDN）

</details>
